# THE BAIGARTS

Original handmade painting showcase + order-request website.
React + Vite + Tailwind CSS v4 + Supabase (Auth, Database, Storage). No customer accounts —
public browsing is fully anonymous; only the artist/admin logs in.

---

## 1. What you need before running this

1. A free [Supabase](https://supabase.com) project.
2. Node.js 18+ installed locally.
3. A WhatsApp number that should receive order notifications.
4. (Optional for now) Your real logo/favicon/OG image — placeholders are already in `public/brand/`.

---

## 2. Supabase setup

### a) Create tables, RLS policies, and storage policies
Open your Supabase project → **SQL Editor** → **New query** → paste the entire contents of
`supabase/schema.sql` → **Run**. This creates the `paintings` and `orders` tables, all indexes,
triggers (auto order numbers, `updated_at`), and Row Level Security policies in one go.

### b) Create the storage bucket
Dashboard → **Storage** → **New bucket** → name it exactly `paintings` → toggle **Public bucket: ON**
→ Create. The storage policies in `schema.sql` already reference this bucket name, so this step
must happen before or after running the SQL — order doesn't matter, just make sure the bucket
name matches exactly.

### c) Create your admin login
Dashboard → **Authentication** → **Users** → **Add user** → enter the email/password you'll use to
log into `/admin/login`. There is no public sign-up form anywhere in this app — this is
intentional, so this is the only way to create an admin account.

### d) Get your API keys
Dashboard → **Settings** → **API** → copy:
- **Project URL**
- **anon public key**

(Never use the `service_role` key anywhere in this frontend project.)

---

## 3. Environment variables

Copy `.env.example` to `.env.local` and fill in your real values:

```
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
VITE_WHATSAPP_NUMBER=923001234567
VITE_SITE_URL=https://thebaigarts.com
```

- `VITE_WHATSAPP_NUMBER` — country code + number, no `+`, no spaces (e.g. Pakistan number
  0300-1234567 becomes `923001234567`).
- `VITE_SITE_URL` — your real production domain once you have one; used for canonical URLs,
  sitemap, and structured data. Fine to leave as-is during local testing.

**Never commit `.env.local`** — it's already in `.gitignore`.

---

## 4. Run it locally

```bash
npm install
npm run dev
```

Visit `http://localhost:5173`. The homepage will show "no paintings yet" until you add one.

Go to `http://localhost:5173/admin/login`, sign in with the admin user you created in step 2c,
and add your first painting from **Paintings → + New Painting**.

---

## 5. Replacing brand placeholders

Everything in `public/brand/` is a clearly-marked placeholder:

| File | What it is |
|---|---|
| `logo.svg` | Text-based placeholder wordmark |
| `favicon.svg` / `favicon.ico` | Simple "B" mark |
| `apple-touch-icon.png` | Same placeholder mark, 180×180 |
| `og-image.jpg` | Plain dark background with brand name, 1200×630 — this is what shows when a link to your site is shared on WhatsApp/Facebook/Twitter |

Replace each file directly (keep the same filename and, for `og-image.jpg`, the same 1200×630
dimensions) whenever you have real logo artwork. Nothing else in the code needs to change.

## 6. Building for production

```bash
npm run build
```

Output goes to `dist/`. Before building for a real deploy, also regenerate the sitemap so it
reflects your current painting slugs:

```bash
npm run sitemap
npm run build
```

`npm run sitemap` reads live data from Supabase, so `.env.local` must be filled in first.

---

## 7. Deploying to Vercel

1. Push this project to a GitHub repo.
2. Import the repo in [Vercel](https://vercel.com/new).
3. Framework preset: **Vite**.
4. Add the same environment variables from `.env.local` into Vercel's **Environment Variables**
   settings (Project → Settings → Environment Variables).
5. (Recommended) Set the build command to `npm run sitemap && npm run build` so the sitemap
   regenerates on every deploy.
6. Deploy.

After it's live: submit your sitemap (`https://yourdomain.com/sitemap.xml`) to
[Google Search Console](https://search.google.com/search-console).

## 9. How the order flow actually works

1. Visitor fills the order form on `/order/:slug`.
2. Form validates client-side.
3. Order is inserted into Supabase `orders` table (status forced to `pending` by RLS —
   the public can never insert an order with any other status).
4. **Only if that insert succeeds**, WhatsApp opens in a new tab with a pre-filled,
   formatted message containing the order number, painting, customer, and full address.
5. If the insert fails, WhatsApp never opens, and the visitor sees a clear error asking
   them to retry — so the admin's WhatsApp never shows a "ghost order" that isn't actually
   saved anywhere.

## 10. Security notes

- The admin route guard (`AdminRoute.jsx`) is a UX convenience only. The actual security
  boundary is Supabase **Row Level Security**, defined in `supabase/schema.sql`.
- Public (anonymous) visitors can only: read paintings, and insert new orders with
  `status = 'pending'`. They can never read, edit, or delete orders — including their own.
- Only authenticated users (your one admin account) can create/edit/delete paintings and
  manage orders.
- The Supabase `service_role` key is never used anywhere in this project.
